New at release 1.3.8

WELCOME!

If this is your first installation of DGUS-Reloaded for CR6Community, I recommend that you:
   a) install and configure Mainsail and Klipper on your system first
   b) modify that base installation, using the following elements of the content in this repository:
      - ~klipper/klippy/extras/t5uid1 (folder and contents)
      - Related Changes (configuration files and klipper.bin file for your motherboard)
   c) install and configure the Stable_Z-Home add-in
   d) tailor your slicer configuration, per any guidance in README.MD
   e) using Mainsail, verify that your system now works correctly, except for the stock display. (Troubleshoot and resolve any issues, if/as applicable.)
   f) return to the DWIN_SET component repository, to flash the matching release of DWIN_SET and integrate the stock TFT display into your system.
   g) verify that the stock display now functions with Klipper, as described in the release notes for that version of the DWIN_SET component.

If you are here to update an existing installation of DGUS-Reloaded for CR6Community, I recommend that you:
   a) replace the contents of the ~klipper/klippy/extras/t5uid1 folder on your Klipper host, with the new version in this release
   b) use Winmerge to compare your current Klipper/Mainsail configuration files with the new configuration files of the same name in the Related Changes folder and incorporate any changes that you see at this release
   c) tailor your slicer configuration, if the Related Changes folder contains any modified instructions at this release
   d) using Mainsail, verify that your system now works correctly, except for the stock display
   e) return to the DWIN_SET component repository, to flash the new release of DWIN_SET and re-integrate the stock TFT display into your system.
   f) verify that the stock display now functions with Klipper, as described in the release notes for the new version of the DWIN_SET component.


New/Modified Features at this release:

 Added back-end processing support for the DWIN_SET v0.4.7 Release:

 - Added a new parameter to variables.cfg, to enable/disable automatic unloading of the filament by the END_PRINT macro
 - Invoke the UNLOAD_FILAMENT macro from the END_PRINT macro, if auto-unload is enabled
 - Modified vars_in.cfg and vars_out.cfg to process the new enable/disable control and to display the current setting

 Modified the CLIENT_VARIABLES section of CR6.cfg:

 - Changed the dz parameter from 10mm to 50mm above the print, when parking the head.  This ensures that the head is parked high enough above the bed to properly view the nozzle for cleaning and to avoid the filament piling up too close to the nozzle, if the head was close to the bed when parked.  

 Added stockprobe.cfg and microprobe.cfg, to support users who replace the stock strain gauge probe system with a BTT MicroProbe sensor
 - NOTE: Other probe sensors will likely require other .cfg files, modelled on the microrobe.cfg file

 Re-mapped the variable addresses assigned to the four configurable FW Retract parameters, to remove an accidental conflict introduced at 0.4.6

 
Bugs/Issues Resolved at This Release:

 - Issue #57 - repaired parameter reference broken by recent Klipper3D update.
 - Issue #58 - added new feature; optional auto unload of filament at end of print


Known Issues at this Release: 
- New Issue #56: Current (Bed_Mesh) Profile name displayed = 'None', if no such mesh stored in printer.cfg (e.g. fresh after a new installation)

- No changes since v1.3.6:
 - The displayed slicer-estimated print time remaining value may toggle between two values, if the print is performed faster than the slicer anticipated (e.g. if the feed rate is increased to a value greater than 100%)
 - The filelist, scroll and delete file scripts expect your gcode files to be stored in the default Klipper Virtual SD card directory:  ~/printer_data/gcodes. If your gcodes are stored in a different directory, they may not work for you
 - I use long filenames, so I designed the list to capture all of the .gcode files in all subfolders, but to NOT display the subfolder names in the list 
  - If you use subfolders to store different versions of files with the same name, you may not like this list.
