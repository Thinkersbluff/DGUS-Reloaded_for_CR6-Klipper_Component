New/Modified Features at this release:

 - #89: Added support for the BTT Smart Filament Sensor v1.0, while retaining the stock switch sensor type as the default config.

 
Bugs/Issues Resolved at This Release:	

 -  #86: Refactored t5uid1.py to resolve problems caused when Klipper renamed and refactored register_response() to register_serial_response().
	- Also added script and documentation support to enable users to roll-back and pin their version of klipper, to restore operations while waiting for a DGUS-Reloaded update.
 -  #85: Built new klipper.bin files, to repair the t5uid1 - DWIN serial interface broken when Klipper refactored mcu.py at Klipper version v0.13.0-557-g54c7b65d.  
	- Added installation files, scripts and guidance to enable users to now rebuild the klipper.bin files any time that a similar mod breaks this interface.
 -  #84: Repaired the Auto_Unload_After_Print function. (Memory address error)
 -  #83: The display switched prematurely away showing the probing screen (checkmarks) almost immediately.  Modified the script to wait until the final probe point before switching.
 -  #81: Rotation Distance was not updating with new value. Corrected data type.
 -  #79: FIRMWARE_RESTART and RESTART take so long to affect the display that one wonders whether the command is running.  Added scripts to present a message screen confirming the actions being taken.
 -  #77: Auto Unload of filament could overspeed extruder, if Flow Rate >> 100. Modified END_PRINT macro to force the flow and federate values back to 100, before homing and retracting.
 -  #76: Corrected the vars_out.cfg script so that The PID menu temperature value defaults to the init_py pla constants instead of to the type1 preset values.


Known Issues at this Release: 
- #82: PID may cause printer Shutdown, if thermistor is stock and [extruder] sensor_type = Honeywell 100K 135-104LAG-J01
- #78: Load_Profile button on Automatic Bed Leveling page sometimes fails to cycle through the profiles
- No changes since v1.3.6:
 - The displayed slicer-estimated print time remaining value may toggle between two values, if the print is performed faster than the slicer anticipated (e.g. if the feed rate is increased to a value greater than 100%)
 - The filelist, scroll and delete file scripts expect your gcode files to be stored in the default Klipper Virtual SD card directory:  ~/printer_data/gcodes. If your gcodes are stored in a different directory, they may not work for you
 - I use long filenames, so I designed the list to capture all of the .gcode files in all subfolders, but to NOT display the subfolder names in the list 
  - If you use subfolders to store different versions of files with the same name, you may not like this list.
