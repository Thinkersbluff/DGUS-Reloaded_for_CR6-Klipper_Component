## Application Architecture Overview

Your application is a Klipper host extension for the DGUS-Reloaded UI, implemented as a Python package under dgus_reloaded. It is designed to interface with a DGUS touchscreen display, providing a rich UI for 3D printer control.

### Key Components

#### 1. **Configuration Files**
- **pages.cfg:**  
  Defines UI pages, their IDs, and the variables (auto-updated or manual) associated with each page.
- **vars_out.cfg & vars_in.cfg:**  
  Define output and input variables, their addresses, data types, and scripts for data transformation or actions.
- **routines.cfg:**  
  Defines routines (scripts) triggered by UI events, page transitions, or manually.
- **presets.cfg & variables.cfg:**  
  Store persistent preset values and runtime variables.

#### 2. **Python Modules**
- **`__init__.py`:**  
  Defines constants, controls, and configuration for the DGUS-Reloaded extension.
- **`page.py`:**  
  Implements the `T5UID1_Page` class, which parses and manages page definitions from pages.cfg.
- **`routine.py`:**  
  Implements the `T5UID1_Routine` class, which parses and manages routines from routines.cfg, handling triggers, delays, intervals, and script execution.
- **`var.py`:**  
  Implements the `T5UID1_Var` class, which parses and manages variable definitions from vars_in.cfg and vars_out.cfg, handling data serialization/deserialization and script execution.

#### 3. **Integration**
- The main entry point is `__init__.py` in the `t5uid1` directory, which loads the DGUS-Reloaded extension.
- The extension loads configuration files, parses them into Python objects (`Page`, `Routine`, `Var`), and manages communication between the Klipper host and the DGUS display.
- Variables and routines are tightly coupled to the UI, allowing dynamic updates and actions based on printer state and user interaction.

## Data Flow

1. **Startup:**  
   The extension loads configuration and preset files, initializes pages, variables, and routines.

2. **UI Interaction:**  
   - When the user interacts with the touchscreen, the display sends variable updates (input) to the host.
   - The host processes these via scripts in vars_in.cfg, which may trigger routines, update variables, or send G-code commands.

3. **Printer State Updates:**  
   - The host updates output variables (in vars_out.cfg) based on printer state, which are sent to the display to update the UI.

4. **Routines:**  
   - Routines in routines.cfg are triggered by page transitions, timers, or manually, and can execute scripts, update variables, or switch pages.

## Extensibility

- **Adding Variables:**  
  Add new variable definitions and scripts to the variable config files.
- **Custom Logic:**  
  Implement new routines in routines.cfg for custom behaviors.
