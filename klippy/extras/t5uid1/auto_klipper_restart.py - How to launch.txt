How to launch auto_klipper_restart.py as a systemd service on your Klipper Host
on a Raspberry Pi or Linux system:

---

### 1. Place your script

Suppose your script is named `auto_klipper_restart.py` and is located at:
```
/home/pi/klipper/klippy/extras/t5uid1/auto_klipper_restart.py
```

Make sure it is executable:
```bash
chmod +x /home/pi/klipper/klippy/extras/t5uid1/auto_klipper_restart.py
```

---

### 2. Create a systemd service file

Create a new file:
```bash
sudo nano /etc/systemd/system/auto-klipper-restart.service
```

Paste the following content (adjust paths if needed):

```
[Unit]
Description=Auto Klipper MCU Restart Service
After=network.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/klipper/klippy/extras/t5uid1
ExecStart=/usr/bin/python3 /home/pi/klipper/klippy/extras/t5uid1/auto_klipper_restart.py
Restart=always

[Install]
WantedBy=multi-user.target
```

---

### 3. Enable and start the service

```bash
sudo systemctl daemon-reload
sudo systemctl enable auto-klipper-restart.service
sudo systemctl start auto-klipper-restart.service
```

---

### 4. Check status

```bash
systemctl status auto-klipper-restart.service
```

---

**That’s it!**  
Your script will now run in the background and restart automatically if it fails or after reboot.

GitHub CoPilot: This is expected behavior based on how Klipper and your script work:

### What’s Happening

- **Power Cycle:**  
  When you power cycle the printer, the MCU disconnects and reconnects. Your script detects this in the log and sends a `RESTART` command, which works as intended.

- **M112 (Emergency Stop):**  
  Sending M112 puts Klipper into a "shutdown" state for safety. In this state, Klipper **requires manual intervention** to restart, and will not respond to API restart commands for safety reasons.  
  This is by design: after an emergency stop, Klipper disables automatic restarts to prevent unsafe conditions.

- **FIRMWARE_RESTART Not Working:**  
  After M112, Klipper blocks all restart commands (including via the API and your script) until you manually acknowledge and clear the shutdown state, usually by running `FIRMWARE_RESTART` from the Klipper console or web interface.

### Why This Happens

- **Safety:**  
  Klipper’s emergency shutdown (M112) is a hard stop intended to prevent automatic or accidental restarts after a potentially dangerous event.  
- **API Limitation:**  
  The Moonraker API (which your script uses) cannot override this safety feature.

### What You Should Do

- **After M112:**  
  You must manually clear the shutdown state (usually by running `FIRMWARE_RESTART` from the Klipper console or web UI).
- **Your Script:**  
  It is still useful for handling power cycles and unexpected disconnects, but it cannot and should not override Klipper’s emergency shutdown safety.

---

**Summary:**  
Your script is working as intended for power cycles.  
After M112, you must manually restart Klipper for safety—this is a deliberate Klipper design and cannot be bypassed by any script or API call.

If you want to restore the previous behavior, you would need to disable or stop your script, but this is not recommended for safety reasons.
