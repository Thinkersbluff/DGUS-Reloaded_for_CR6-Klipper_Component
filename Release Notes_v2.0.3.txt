New/Modified Features at this release:
1. Added an echo of the probe.py responses, as the printer runs ABL or runs PROBE_ACCURACY.  
   The message field now displays the latest "z=" probe value and the range between the samples taken to that point.  
   Allows users to monitor the probing process. Any mechanical problem  with the probe assembly itself should evidence a significant deviation from expectations.  In such cases, the probe will continue to take samples until either the range falls within the configured constraint of 0.02mm or the probe exhausts its permitted max number of attempts.
2. Added a new macro function, "DGUS_SET_MESSAGE" in t5uid1.py.  
   This allows macros to send a message to the printer screen, because RESPOND can not.
3. Added a new macro function "DGUS_FILAMENT_MOVE" to DGUS-Reloaded.cfg
   This allows t5uid1.py to invoke the change filament LOAD/UNLOAD functionality via a macro, removing a Jinja2 timing vulnerability from the previous implementation.
   It also makes it a little easier for users to define/modify the functionality, if they wish.
   Added new logic to that function, to prevent LOAD or UNLOAD if the current extruder temperature is above the min_extrude temperature when the button is pressed, but is actually dropping because the heater itself has been turned off.  This prevents accidental issues with LOAD/UNLOAD in cases where heaters time out and the user has not noticed.
   This function also lays the groundwork for a future modification that will implement printer awareness of which filament type is currently installed on the printer.  This would allow implementing different min_extrude temperatures for each filament type, for instance.

Known Issues at this Release: 
- No changes since v1.3.6:
  - The displayed slicer-estimated print time remaining value may toggle between two values, if the print is performed faster than the slicer anticipated (e.g. if the feed rate is increased to a value greater than 100%)
  - The filelist, scroll and delete file scripts expect your gcode files to be stored in the default Klipper Virtual SD card directory:  ~/printer_data/gcodes. If your gcodes are stored in a different directory, they may not work for you
    - I use long filenames, so I designed the list to capture all of the .gcode files in all subfolders, but to NOT display the subfolder names in the list 
    - If you use subfolders to store different versions of files with the same name, you may not like this list.

If a future Klipper update renders your system inoperable, you can try rolling the Klipper on your system back by pinning it to this version, as follows:

SSH into your host and run these commands:

###

cd ~/klipper
sudo systemctl stop klipper
git fetch --all --tags
git checkout 2fb3d54e2f8086fb310936c9136dbb05dc753ed5
git rev-parse --short HEAD
sudo systemctl start klipper
sudo systemctl status klipper --no-pager

###

Note: “detached HEAD” is normal when pinned to a specific commit.
To return to normal tracking later: git switch master (or your usual branch) and then git pull.
