New/Modified Features at this release:
  - Modified key [extruder] section parameters in printer.cfg for Orbiter/Dragon HF combo. See the embedded comments for the recommended stock extruder/hotend values
  - Tweaked the amount of filament extruded prior to Unloading Filament, from 5mm to 15mm, to better ensure that any blob at the tip gets removed.
  - Modified the Pi-Side Scripts and Appendix E to use sudo nano instead of trying to create the files with bash scripts.
    Also simplified the workflow, to only require substituting the MCU Serial ID value into the templates.

Bugs/Issues Resolved at This Release:	
#91 - Release 2.0.0 shows v1.4.4 on the Info screen??
 - Bumped version# to 2.0.1 in vars_out.cfg
#92: The RESTART and FIRMWARE_RESTART buttons on the boot screen do not work when printer is first powered-up
 - Installing the Pi-side scripts solves this problem, by restarting the mcu comms automatically upon printer power-up.
#93 - Building a new klipper.bin file per the instructions in Appendix A of the Installation Manual, after Moonraker updates the Klipper files, results in an error, "mcu 'mcu': Unknown command :t5uid1_ping"
 - Moved the dgus_reloaded shell scripts from ~/klipper/scripts/dgus_reloaded to ~/printer_data/config/scripts
      Reason: ~/klipper/ is a git-tracked directory managed by Moonraker. When Moonraker runs git pull to update Klipper, git can overwrite or remove files in that tree. Any scripts stored under ~/printer_data/config/scripts/ are therefore at risk of being deleted or disrupted by a routine Klipper update.
              ~/printer_data/config/ is not a git repository and is never touched by Moonraker's update process. It is the standard location for user-managed files (configs, macros, scripts). Files placed there survive every Klipper update unconditionally.
 - Clarified the instructions in the Installation Manual, re: how to ensure the presence of the patches to the stm32 KConfig and Makefile before attempting to make a new klipper.bin

Known Issues at this Release: 
- #82: PID may cause printer Shutdown, if thermistor is stock and [extruder] sensor_type = Honeywell 100K 135-104LAG-J01
- No changes since v1.3.6:
  - The displayed slicer-estimated print time remaining value may toggle between two values, if the print is performed faster than the slicer anticipated (e.g. if the feed rate is increased to a value greater than 100%)
  - The filelist, scroll and delete file scripts expect your gcode files to be stored in the default Klipper Virtual SD card directory:  ~/printer_data/gcodes. If your gcodes are stored in a different directory, they may not work for you
    - I use long filenames, so I designed the list to capture all of the .gcode files in all subfolders, but to NOT display the subfolder names in the list 
    - If you use subfolders to store different versions of files with the same name, you may not like this list.

This release was validated against:

If a future Klipper update renders your system inoperable, you can try rolling the Klipper on your system back by pinning it to this version, as follows:

SSH into your host and run these commands:

###

cd ~/klipper
sudo systemctl stop klipper
git fetch --all --tags
git checkout 373f200ca69adb624675f42e685f61d85d49ba40
git rev-parse --short HEAD
sudo systemctl start klipper
sudo systemctl status klipper --no-pager

###

Note: “detached HEAD” is normal when pinned to a specific commit.
To return to normal tracking later: git switch master (or your usual branch) and then git pull.
